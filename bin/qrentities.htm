QUAKE RALLY ENTITIES
Custom Entity Documentation

The following documentation details all the special entities you can use to create Quake Rally maps. Most entities and keys aren't required at all to make maps work in QR, only the entities listed in green are the very important ones. All entities and keys must be lowercase or they will not work.

SPECIAL NOTES:

* The are two entities which MUST be in a Quake Rally map for it to work correctly; the race_type key in the worldspawn entity, and at least one info_player_deathmatch.
* If the map is a racing map (either with weapons or without), then there are two types of entities that MUST be additionally in the map; rally_startfinish(_brush) and rally_marker. If you want a visible waving flag in your map, you will also need to add a rally_startfinish_flag at the appropriate location.
*

Many of the entities listed are available in two flavours; fixed-size and _brush. If you use the "fized-size" variety, then you should read the next Special Note too, but generally you will always want to use the "_brush" variety.

In Worldcraft, these entities are created by first constructing a brush exactly where you want the entities "area of trigger" to be, and then clicking on "ToEntity" which will then turn that brush into an entity. Other editors probably work in a similar way. This has the benefit of giving you total control over the "area of trigger" for that entity.

*

This only applies if you find you need to use fixed-size brushes; all the entities that have a fixed size of (-128 -128 -24) (128 128 16) can have their X & Y extreminites altered by setting the "speed" key for the entity to a number other than 128. eg. if I were to say:

"speed" "64"

Then that entity will be created with a bounding box of (-64 -64 -24) (64 64 16).

*** IMPORTANT: Setting the bounding boxes correctly is vitally important because a fixed-size entity will NOT work if it touches or cuts into the walls of the map.

GENERAL ENTITIES

rally_jump_brush entity bound to a brush of user size/shape

This tells the code that the next time the car becomes airborne, extra upwards velocity should be applied. These should be placed at the base or somewhere along the jump, such that the top of the jump is reached within 2 seconds of touching the rally_jump entity. This entity is only needed if you want to do a mega-jump.

Keys/Values: (no keys required)

rally_changesurface fixed size (-128 -128 -24) (128 128 16)
rally_changesurface_brush entity bound to a brush of user size/shape (prefered)

This tells the code that the current surface being driven on has changed. Ideally used when changing from a dirt segment of track to bitumen, or vice versa. Unfortunately this surface changing is really only workable in racing maps instead of DM maps.

Keys/Values:

current_surface 1 (mud)
2 (asphalt)
3 (grass)

worldspawn NOTE: this entity is a builtin entity type, you do not add it yourself.

Important: The worldspawn entity is a "builtin" entity to all maps and should not be created by hand. It's important in Quake Rally because QR uses a new key called race_type. This additional key defines the default game mode of the map. In Worldcraft, this special entity is edited via the "Map Properties" tool (remember, you need to turn off 'SmartEdit' to add a key), or in the .map file it's the entity at the top like:

{
"classname" "worldspawn"
"nexttrack" "qrally02"
.
.
}

This key MUST be set for all Quake Rally maps if you wish them to play correctly.

Keys/Values:

race_type
racing - pure racing, no weapons
racing_dm - racing with weapons
dm - pure Deathmatch

info_player_deathmatch (has no size)

This is a standard entity from Quake and is used for all player start points in a Quake Rally map (ie. QR does not use the info_player_start entity). QR currently supports up to 8 players so always have at least 8 of these entities.

Keys/Values:

angle "angle for car to face"

RACING ENTITIES

rally_marker (has no size)

This is one of the essential entities IF the map type is one of the two racing styles.

The entity is used to validate that a player has completed a lap. Markers are placed around the track, preferably at the beginning and end of each straight, with a limit of 12 markers per track. This is vital for the position calculation code to work accurately. If a player destroys their vehicle, they will respawn at the last marker touched, and will be facing the direction specified by the marker. Markers are visible in time trial as flags.

Markers are numbered starting at 1 and the code checks to see that the player has gone past each marker in the correct progression (ie. the player MUST go through in order of 1 2 3 4 etc). The angle key is also used to determine whether or not the player is driving in the correct direction.

The rally_marker entity, unlike most others in QR has no size, instead the code considers that a car has touched it if it comes within 384 units of the marker location (or 64 units if the skill is >1 and you are in "Time Trial" mode). Keep this in mind when placing markers.

Keys/Values:

ammo_shells "marker index number (starting with 1)"
angle "direction to face player upon respawn"

rally_startfinish fixed size (-128 -128 -24) (128 128 16)
rally_startfinish_brush entity bound to a brush of user size/shape (prefered)

This is one of the essential entities IF the map type is one of the two racing styles.

This entity identifies the start and end of a racing map although it is separate to the "visible" flag which is placed by the rally_startfinish_flag entity. Upon touching this entity, the code checks to make sure each marker has been activated in sequence, if so, the lap is awarded. You may only place one of these in each map.

This entity uses two keys; one to tell it how many markers are to be found in the map and one to tell it how many laps the race will be.

Keys/Values:

ammo_shells "number of markers in the map"
ammo_nails "number of laps to complete the race"

rally_startfinish_flag (has no size)

This is the visible start/finish flag. Since it's separate to the actual trigger it can theoretically be placed anywhere, although it would be best to place it near the rally_startfinish_brush entity somewhere.

Keys/Values: (no keys required)

WEAPON ENTITIES

weapon_repulsor non-recharable (wears down from use)
weapon_supernailgun uses standard Quake "nails" ammo
weapon_detonator uses standard Quake "missile" ammo
weapon_minelauncher uses standard Quake "missile" ammo
weapon_rocketlauncher uses standard Quake "missile" ammo
weapon_lasergun uses standard Quake "charge" ammo

All other weapon entities will be ignored by QuakeRally so don't bother placing grenades or shotguns in maps. Other Quake entities such as the pentagram and quads do work although are unsupported.

All three varieties of health from Quake are supported in QuakeRally however their values are changed somewhere. Small (rotten) health is worth 5 health points (as apposed to 10 in Quake). The aim is that these are to be spread out quite heavily around the map allowing easy, but small, top-ups on a regular basis. The normal health packs are worth 15 (Quake usually gives 25) so these are designed to be a little harder to get but worth hunting out if you are close to death.

ENVIRONMENTAL ENTITIES

rally_cone

Places an orange cone at the specified location. The cones are placed the same as health and other items, so they are dropped to the floor automatically. Cones are an interactive map element meaning that the cars can knock them around.

Keys/Values: (no keys required)

rally_baracade fixed size (-16 -16 0) (16 16 8)

Same as cones, except these are larger in size.

Keys/Values:

angle "angle for flat side of barracade"

rally_stopsign

Places a stopsign at the given location.

Stopsigns should only be placed on level ground. Otherwise they may look dis-oriented if knocked over at low speeds.

Keys/Values:

angle "angle to face sign"

MISCELLANEOUS ENTITIES

rally_spawn_dude

Spawns a Duke Nukem at the given location. Each time a Duke dies, another is spawned at a random rally_spawn_dude location, therefore if you place 5 of these in your map, you will always have 5 Dukes running around (enough to give anyone nightmares).

Keys/Values: (no keys required)

rally_spawn_kangaroo

Same as rally_spawn_dude except a kangaroo is spawned instead.

Keys/Values: (no keys required)

rally_kangaroo

Spawns a kangaroo at the given location. When this roo dies, it does not respawn.

Keys/Values: (no keys required)
